## 요약
경기 상대를 구하기 어려운 스포츠인을 위한 경기 매칭 서비스. 한정된 상대 팀, 경기 성사까지의 시간 소모·불편함을 해결하기 위해 실력을 객관적 수치로 환산하는 **Rating Point System**을 도입했다. 사용자는 원하는 날짜·시간·장소만 선택하면 실력이 균형 잡힌 상대와 자동 매칭된다. Rating Point System은 **ELO Rating 알고리즘**(국제체스연맹 공식 랭킹, FIFA 랭킹 산정 등에 사용)을 바탕으로 고안했고, 기록이 쌓일수록 정확도가 올라간다. e-sports 특유의 요소를 오프라인 스포츠에 도입해 부흥·활성화를 유도하고자 했다.

## I. 서론
- 강원대 컴퓨터정보통신공학 축구동아리 'CLASS' 21명, 농구동아리 '어우동' 9명 대상 설문: 현재 경기 방식 만족도 **5점 만점 3.5점**, 주된 감점 사유는 "항상 같은 상대와의 경기 매칭"
- 이에 **Auto-matching Algorithm**과 **Elo Rating System**을 연구하고 이를 적용한 앱을 개발
- Auto-matching: 같은 지역·날짜로 매칭 등록 → JSON으로 DB 전송 → 날짜별 분류 저장 → 신청 날짜 3일 전까지 누적 후, 3일 전이 되면 알고리즘으로 가장 적합한 팀끼리 매칭

## II. 관련 연구
### 2.1 Elo Rating
현재 레이팅 $R_a$, 경기 후 레이팅 $R_a'$, 중요도 상수 $K$, 실제 결과 $S_a$(승 1 / 무 0.5 / 패 0), 기대 승률 $E_a$일 때

$$R_a' = R_a + K(S_a - E_a), \quad E_a = \frac{1}{1 + 10^{(R_b - R_a)/400}}$$

(Bradley–Terry 모델 기반 기대 승률) — $R_b'$도 동일하게 계산.

### 2.2 Auto-matching Algorithm
자체 알고리즘. DB 설계는 잡 매칭 알고리즘(직종·지역·임금 등 조건 일치 추출)을 참고. 회원이 지역·구장·날짜·시간을 선택해 신청하면 같은 조건의 회원을 같은 스키마에 저장하고, 3일 전 시점에 레이팅이 가장 비슷한 두 팀을 매칭. DB 구조를 동적으로 생성·수집.

## III. 앱의 설계 및 구현
- 역할 분담·과제 관리는 분산형 관리 방식
- 요구사항 분석: 동아리원 대상 설문으로 앱 방향성 결정 → 시제품 개발
- 레이팅·매칭·코인 등 오래 걸리는 부분은 뒤로 미루고 프론트엔드와 빠르게 개발 가능한 백엔드를 우선 구현
- 매칭은 선착순, 레이팅은 단순 승점제로 시작 → 시제품 평가로 버그 체크 → 레이팅·매칭 기술 연구 후 접목해 완성
- 회원가입 시 팀 선택/생성
- 화면: 메인(축구·야구·농구 카테고리, 일정관리, my page, my team) / 축구 카테고리(랭킹·팀·지역·RP·승률 표) — 앱 이름 **HANTTEU**
  - 이미지: 그림 1 메인 화면(p2), 그림 2 축구 카테고리 화면(p3)

## IV. 실험 및 성능 평가
### 4.1 실험 환경
가상 팀 10개 생성 → 레이팅·승률 조정 → 상위 6개 팀을 같은 시간·날짜·장소로 총 10회 매칭

| 팀 | 레이팅 |
|---|---|
| FCknuit | 1640 |
| 파스타FC | 1550 |
| FCDOGSS | 1325 |
| FCSINBA | 1231 |
| FC SOOLO | 1209 |
| FC KICKS | 1190 |

### 4.2 결과
- 10회 모두 FCSINBA–FC SOOLO가 우선 매칭(가장 비슷한 수준) → 이전 매칭 결과와 독립적으로 매칭되는 문제 발견
- **개선**: 직전 매칭 데이터를 다음 매칭 우선순위에 반영 — 최근 매칭된 팀은 낮은 우선순위, 최근 매칭이 없던 팀에 높은 우선순위 부여

## V. 결론
- 매칭 알고리즘 + ELO 레이팅으로 다양한 경기 매칭 제공
- 기술적: 오프라인 스포츠에 e-sports 요소(레이팅 포인트) 도입, 역량에 맞는 오토매칭
- 사회적: 쉽고 빠른 매칭으로 오프라인 스포츠 활성화
- 적용 범위: 대학별 경기 매칭, 아마추어 스포츠 활성화, 전적 기록, 일정 관리
